# عقلان سنتر برو — سجل التنفيذ

المالك: الدكتور عقلان الكامل. المستودع خاص، والمشروع الجديد مستقل عن أنظمة المركز الحالية.

## الحالة الفعلية — 2026-10-05

تم إنشاء المستودع وتنفيذ نواة حسابية مستقلة مع 10 اختبارات ناجحة محلياً على Node 24.
لا توجد بعد واجهة تشغيل أو قاعدة بيانات أو نشر على Railway. لا تستخدم هذه النسخة لإدخال مرضى حقيقيين.

## القرار المعماري

نظام موحد بوحدات واضحة داخل تطبيق خلفي واحد وقاعدة PostgreSQL؛ واجهة عربية RTL، موقع العيادة وبوابات المرضى والعاملين وتطبيقاتهم تتصل بنفس واجهات الخدمة. الاستضافة المستهدفة للواجهة والخلفية وقاعدة البيانات Railway. لا تنشأ سجلات مالية منفصلة في التطبيقات. ملف المريض والخطة والزيارة والإجراء هي المراجع المشتركة لجميع التخصصات.

حدود الوحدات: الهوية والفروع والصلاحيات؛ المرضى والأرشفة والاستيراد؛ الخطط والتخصصات؛ الزيارات والإحالات؛ المواعيد والطابور وشاشة الصالة؛ دفتر الحسابات والتحصيل؛ المعامل والموردون والمخزون؛ الموظفون والعمولات؛ الرسائل؛ التقارير والإعدادات. التخصصات تشمل التقويم وعلاج الجذور واللثة والتركيبات والزراعة والجراحة والأطفال وطب الفم والتصوير.

## ما ينفذه الكود الحالي

- قيم مالية نصية وحسابات BigInt بوحدات جزء من مئة للعملات YER/SAR/USD، بلا floating point.
- سعر الصرف بوحدة عملة السداد لكل وحدة من عملة الدين؛ مثال 14000 يمني بسعر 140 يمني/سعودي = 100 سعودي. السعر مثال اختباري وليس سعراً حالياً.
- حفظ اتجاه التحويل وطريقة التقريب وباقي التقريب حسابياً. لا يُعاد تسعير التحويل القديم بسعر اليوم.
- مراجعة الاتفاق القديم والمدفوع السابق؛ المجهول أو المتنازع عليه يمنع توليد مقترح الرصيد.
- مقترح قيد افتتاحي بالمتبقي فقط، بلا إيراد جديد أو تحصيل نقدي أو فاتورة وهمية؛ الزيادة السابقة تظهر كرصيد دائن للمريض.
- ربط المقترح بمعرف المريض والخطة والفرع والمصدر والمراجع. هذه معرفات في مقترح فقط؛ التحقق من وجودها وعلاقاتها لم ينفذ بعد.

## بوابة التنفيذ التالية: الحفظ الآمن

قبل أي واجهة تحصيل: مخطط قاعدة بيانات ومهاجرات مراجعة؛ صلاحيات خادمية؛ قيود روابط المريض والخطة والفرع؛ معاملة ذرية للقيود والتدقيق؛ مفتاح منع تكرار محفوظ وفريد في قاعدة البيانات؛ اختبارات تزامن وتراجع المعاملة؛ التصحيح بقيد عكسي مع السبب لا تعديل القيد السابق. مفتاح المصدر في النواة الحالية لا يمنع التكرار منفرداً.

الحقول المالية السابقة توثق المجموع والمدفوع والعمل المنجز ومصدر الإثبات وتاريخ القطع لكل خطة وعملة. لا تجمع واردات Mini والورق والنظام المكتبي تلقائياً: معاينة استيراد، اكتشاف تداخل، مطابقة واعتماد بشري، سجل كل صف وسبب قبوله أو رفضه. الملف المشترك بين أفراد الأسرة ليس دليلاً على تطابق المريض.

## تسلسل الإنجاز

1. قاعدة البيانات والهوية والفروع والصلاحيات وسجل التدقيق واختبارات المعاملات.
2. ملف المريض الموحد وإدخال الحالة السابقة والاستيراد بمعاينة ومطابقة، ثم رصيد الخطة.
3. رحلة كاملة: حجز/وصول → زيارة وإجراء مرتبط بالخطة → تحصيل بعملة مختلفة → خروج وكشف حساب.
4. التقويم ضمن الخطط: التشخيص والوثائق والأهداف والمراحل والشدود والتوقيع مرة واحدة والتثبيت. وحدة «سيفالو د. عقلان الكامل» ضمن التصوير، مع تحقق القياسات قبل استخدامها سريرياً.
5. بقية التخصصات والإحالات والمعامل والموردون والمشتريات والعمولات والتقارير.
6. إعدادات الهوية والشعار والأسعار والنماذج والصلاحيات؛ شاشة الصالة والحجز الإلكتروني والرسائل SMS/WhatsApp/Email عبر مزودين معتمدين وحالات تسليم ومنع التكرار.
7. موقع العيادة وبوابات المرضى والعاملين ثم التطبيقات، كلها على نفس الخدمات.
8. بيئة تجريبية على Railway؛ اختبار الاستيراد والمصالحة المالية والاستعادة من نسخة احتياطية قبل اعتماد التشغيل الفعلي.

## قواعد الجودة والحقوق

لا تُعتبر هذه الخطة ضماناً لانعدام الأخطاء. كل مرحلة لها اختبارات قبول وقيود معلنة. لا بيانات مرضى أو مفاتيح سرية في المستودع. لا تخطي لاختبارات فاشلة أو بوابة أمان لإتمام النشر. لا تسمح الإعدادات بإلغاء قيود سلامة الحسابات. لا تنسخ كود يولو أو هويته؛ الفيديو مرجع لسير العمل فقط. حقوق الكود المخصص للدكتور عقلان الكامل؛ تراخيص مكونات الطرف الثالث تبقى لأصحابها.
