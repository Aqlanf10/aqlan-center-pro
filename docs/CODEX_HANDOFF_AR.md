# تسليم التنفيذ إلى Codex — عقلان سنتر برو

تم التسليم بطلب الدكتور عقلان الكامل بتاريخ 2026-10-05، توقيت آسيا/عدن. التنفيذ ينتقل إلى جلسة Codex الجديدة. جميع الوكلاء في الجلسة السابقة أنهوا مهامهم؛ لا يوجد منهم تطوير متوازٍ مستمر.

## تعليمات المالك الملزمة

أكمل **الخطة الشاملة بالكامل** على نفس المشروع؛ لا تبدأ مشروعًا بديلًا ولا تعِد كتابة ما يعمل بلا سبب مختبر. العربية اللغة الأساسية والافتراضية، والإنجليزية لغة ثانية كاملة مع RTL/LTR. كل التخصصات والفروع والعملات والحالات الجديدة والقديمة مشمولة. مسموح بالعمل المتوازي مع توزيع ملكية الملفات، وبدمج الفرع المكتمل بعد مراجعة ونجاح فحوصه على رأسه الفعلي. لا توقف كل مرحلة لطلب تأكيد روتيني داخل التفويض، ولا تدّع الجاهزية قبل دليلها.

الاستضافة المطلوبة Railway للواجهة والخلفية وPostgreSQL. اسم البرنامج عقلان سنتر برو، وحقوق الكود المخصص للدكتور عقلان الكامل؛ وحدة السيفالو باسمه. المستخدم لا يقبل تكرار التشتت والديون التقنية أو وحدات تعمل منفصلة.

## المنفذ ضمن الأساس — وليس البرنامج الكامل

- عمليات نقدية دقيقة YER/SAR/USD، واتجاه صرف صريح: عملة السداد لكل وحدة من عملة الدين.
- افتتاحيات قديمة بالمتبقي فقط، مجهول/متنازع عليه يمنع التفعيل، ورصيد دائن تاريخي دون نقد وهمي.
- PostgreSQL: المريض والفروع والأدوار والخطط والإجراءات والأسنان والزيارات، ودفتر قيود وأثر تدقيق ومنع تكرار دائم.
- أوامر ذرية ومسار جديد وقديم، مراجعة مسودة قديمة قبل التفعيل، سداد وتحويل وعكس إيصال مع سبب.
- جلسة موقعة مرة واحدة دون تحصيل إضافي تلقائي؛ قيود تمنع الربط بين مريضين.
- خادم Node HTTP، scrypt وجلسات مجزأة وصلاحيات وCSRF، وقراءات حسب الفرع والصلاحية.
- حساب تشغيل محدود وSECURITY DEFINER لأوامر محددة؛ ليس مالك المخطط. هذه حدود خادم موثوق وليست RLS.
- واجهة web/ ثنائية اللغة متصلة بهذه API، تتضمن المرضى والخطط والجلسات والسداد وكشف الحساب.
- معاينة CSV فقط واكتشاف مشكلات/تكرار ومجاميع منفصلة العملات؛ ليست استيرادًا مرحّلًا.
- validators سريرية أولية لكل تخصص، وتقويم/عصب/لثة؛ ليست ملفات تخصص مكتملة أو مربوطة كلها بالواجهات والحفظ.
- مهاجرات checksum واختبارات تزامن، وملفات تمرين backup/restore وDocker وRailway.

## الأدلة الدقيقة والقيود

- آخر تشغيل محلي كامل عند التسليم: `npm test` — **61 نجاحًا، 0 فشل، 0 تخطٍّ** على Node 24.19.0، مع PGlite لاختبار محرك PostgreSQL محليًا.
- CI أخضر سابق: run **37241218521** عند SHA `72bb1ea62452963a1bf830d750f857141866fcb5`: Node + PostgreSQL 17 migrations/replay/concurrent overpayment/idempotency.
- ذلك النجاح **لا يغطي تلقائيًا** أحدث إضافات web/ وlegacy.review وclinical/import preview وbackup/restore وبناء Docker. افحص آخر CI بعد تسليم أحدث الرأس.
- CI سابق فشل بسبب تمرير URI في PGDATABASE؛ أصلح باستخدام scripts/pg_support.py، ثم نجح الفحص التالي. لا تخفِ هذا التاريخ.
- التحقق البصري والمتصفح الفعلي ما زال غير منجز: محاولة localhost أعادت ERR_BLOCKED_BY_CLIENT في بيئة العمل السابقة. اختبارات HTTP ليست بديلًا عن اختبار الواجهة.
- pg 8.23.0 وقفل اعتمادياته نُقلا من package-lock.json المرجعي لـMini عند `e66a2b48e2bb2a7714a35d293a9ece9824e27e3f` مع نسخ version/resolved/integrity كما هي؛ npm ci وaudit في CI هما بوابة التحقق. PGlite للتطوير فقط، لا fallback إنتاجي.
- لم يُنشأ نشر جديد على Railway لهذا البرنامج. لا مخطط إنتاج مطبق، ولا استيراد مرضى حقيقيين، ولا حساب مدير إنتاج مُجهز.
- المستودع أنشئ Private؛ آخر metadata أثناء العمل أظهر Public. تحقّق من اختيار المالك الحالي؛ لا تُدخل أسرارًا أو بيانات مرضى ولا تغيّر الظهور بلا سبب وتفويض.
- أي 1.6/IMPLEMENTATION قديم يذكر «لا قاعدة بيانات/خادم» يعكس وقت أول نواة؛ سجل الحالة وهذا التسليم أحدث منه.

## أول دورة عمل لك

1. اسحب main وفرع PR #1 وافحص git status والفروق؛ حافظ على كامل خطة main. أعد قراءة أحدث الرأس وليس SHA الأخضر القديم.
2. نفذ npm ci وnpm test، وفحص الإنتاج الأمني وبناء Docker. افحص آخر GitHub Actions وجوب PostgreSQL وrestore الجديد وأصلح الفشل، دون تخطي اختبار.
3. نفذ بيئة تطوير واختبار متصفح عربية/إنجليزية: جديد → خطة → إجراء → زيارة/توقيع → سداد بعملة أخرى → كشف؛ وقديم مجهول → مراجعة → تفعيل مرة واحدة → متابعة. تحقّق من الهاتف وRTL/LTR والحقول المحمية ورسائل الخطأ.
4. راجع الأمان والتزامن والاستعادة والصلاحيات، ثم حوّل PR #1 إلى جاهز وادمجه فقط عند اكتمال نطاق الأساس. هذا الدمج لا يعني قبول التشغيل السريري الكامل.
5. جهّز Railway مع حساب هجرات منفصل عن التشغيل وأسرار مُدارة؛ لا default password ولا تعطيل التحقق من TLS. اختبر staging ثم تحقق الاستعادة قبل أي بيانات حقيقية.
6. أكمل المصفوفة على مراحل رأسية مرتبطة: الاستقبال/الكشف/الأقساط/المواعيد/الصالة، ملفات التخصصات المتكاملة والإحالات، الفواتير والصناديق والتصحيح التاريخي، الاستيراد المعتمد، المعامل والموردون والمخزون والعمولات والموظفون والتقارير والإعدادات، الموقع والبوابات والرسائل والتطبيقات. لا تعدل ترتيب الخطة بصمت ولا تختزلها في الأساس الحالي.
